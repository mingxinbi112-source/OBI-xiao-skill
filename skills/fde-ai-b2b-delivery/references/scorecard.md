# FDE B 端交付 Go/No-Go 完整打分表与话术库

本文件是 `SKILL.md` 的量化扩展。用法:给具体项目逐项打分 → 按权重加权求和 → 用分数阈值判定每阶段 Go / Hold / No-Go → 任一阶段 No-Go 即整体一票否决。

**打分证据纪律:** 每一项的得分必须引用客户访谈原话、文档、数据样本等具体事实作为依据(可记为"证据:____"),禁止按"客户用了多少高级名词/态度多热情"给分;没有可引用证据的项按 0 分或标"未取证"处理,不许拍脑袋补分。若某项触及致命红线(数据出境违规/无授权训练客户数据/不可逆决策交 AI 拍板等),单独记录为否决项,不被加权总分平均掉——总分再高,否决项存在即整体 No-Go。

## 目录
1. 阶段一打分表(签约前体检,权重 35%)
2. 阶段二打分表(人际破局,权重 20%)
3. 阶段三打分表(MLOps 架构,权重 30%)
4. 阶段四打分表(预期管理,权重 15%)
5. 总分决策矩阵
6. 话术库扩展版

## 一、阶段一:签约前体检打分表(权重 35% — 决定签不签,最该严)

评分规则:每项 0/1/2(0=否/高风险,1=部分/中等,2=是/低风险)。权重为该项目占整体(四阶段合并 100%)的比例。

| 维度 | 检查项 | 0 分 | 1 分 | 2 分 | 权重 |
|---|---|---|---|---|---|
| 数据成熟度 | 真实样本 3-5 个 | 支吾不给 | 勉强给 | 爽快给 | 8% |
| 数据成熟度 | 数据载体 | 脑子/Excel | 部分系统化 | 全在系统 | 6% |
| 数据成熟度 | Owner 与维护频率 | 无 Owner | 有但不稳 | 明确+定期 | 4% |
| 数据成熟度 | 合规边界 | 不清 | 部分清晰 | 清晰(训练授权/出境) | 4% |
| 系统集成度 | 核心系统 API/可改 | 无/封闭 | 部分 | 有文档可改 | 6% |
| 系统集成度 | IT+合规审批周期 | >6 个月 | 8 周–6 月 | ≤8 周 | 5% |
| 系统集成度 | 接入真实业务流 | 旁路网页 | 部分接入 | 深度融合 | 5% |
| 人际博弈 | 接触一线使用者 | 不能 | 间接 | 直接 | 6% |
| 人际博弈 | 利益受损方权重 | 大且强势 | 中 | 小/受益 | 4% |
| 成功标准 | 指标量化可验收 | 模糊"提效" | 部分量化 | 清晰可验收 | 6% |
| 成功标准 | Plan B | 无 | 口头 | 书面 | 3% |

**阶段一加权得分阈值(该阶段满分折算为该阶段小计):**
- ≥ 75%:**GO**(可签)
- 50%–74%:**HOLD**(先做 1-2 周数据可用性 mini 验证)
- < 50%:**NO-GO**(死局,放弃或重构范围)

> **KPI 分层提示:** 上表"成功标准"行的"指标量化可验收",至少要锁**业务层**(adoption / 完成率 / 人工替代率 / 成本改善)+ **质量层**(准确率 / 复核通过率 / 路由正确率)两层;系统层、数据层指标在阶段三补齐。企业真正认的是 adoption 和单位产出,不是模型 benchmark。四层 KPI 体系见 `references/production-architecture.md`。

> **交付范围六层闭环提示:** 上表只评"能不能签",没评"签下来要做多深"。签约前务必再用「Sense→Understand→Reason→Decide→Act→Learn」定位交付落在第几层(看板/问答 vs 决策闭环,工期差一个数量级),并评估 Ontology(业务语义)成熟度 L0-L3——这决定本体建设工期,直接影响报价与排期。诊断框架与评估表见 `references/decision-os-playbook.md`。

## 二、阶段二:人际破局打分表(权重 20%)

| 检查项 | 0 分 | 1 分 | 2 分 | 权重 |
|---|---|---|---|---|
| 关键老员工认同度 | 公开/隐蔽抵制 | 中立观望 | "功臣"认同 | 7% |
| 每周配合投入 | 拒绝 | <1 小时 | 2-3 小时 | 4% |
| 已替其干掉痛点杂活 | 0 项 | 筹备中 | ≥1 项已兑现 | 5% |
| 荣誉绑定(冠名/署名/审核权) | 无 | 口头承诺 | 已落地 | 4% |

**阈值:** ≥ 70% GO / 40%–69% HOLD(加码荣誉绑定+先兑现甜头)/ < 40% NO-GO(升级管理层或绕开)。

> 🟠 **人际红旗(Hold 信号):** 若阶段二只做了话术重构 + 荣誉绑定 + 干脏活,却**没设计任何结构性配合机制**(上级 KPI 绑定 / 重定义角色 / 书面利益绑定 / 横向多专家交叉验证降单点依赖——五种机制一个都没用),记为人际 Hold。靠情怀换不来秘密:你等于在专家面前组装一台"替换他自己"的机器,单靠话术撬不出压箱底的例外条款。五种机制与专家类型诊断见 `references/expert-knowledge-extraction.md`。

> **隐性知识抽取深度提示:** 上表"关键老员工认同度 / 每周配合投入"评的是"愿不愿意配合";但**配合了之后抽没抽出真知识**是另一回事。签约后两周内,应能用三手法之一(影随 think-aloud / CDM 关键决策法 / 对比反例)抽出至少 1 条**带例外条款的决策树**(触发→判据→动作→例外)。只抽到"步骤流水"或"正确的废话"= 抽取失败,等于没拿到隐性知识——这条不进打分权重,但是人际 Go 之后必须复核的硬指标。抽取 SOP 见 `references/expert-knowledge-extraction.md`。

## 三、阶段三:MLOps 架构打分表(权重 30% — 决定上不上生产)

**阶段三权重说明(v1.2 重排):** 治理类(人机边界 + 权限 + 审核)= 14%,MLOps 骨架类 = 16%,合计 30% 不变。agent 时代,"权限与人工监督"和 MLOps 骨架同等重要——前者缺位,系统死在越权与审核形同虚设;后者缺位,系统死在不可复现与无法回滚。

| 骨架 / 边界 | 优先级 | 0 分 | 1 分 | 2 分 | 权重 |
|---|---|---|---|---|---|
| 人机边界 A/B/C 已定义并留接口 | — | 未分 | 部分分 | 全分+接口 | 3% |
| C 类不可逆决策 = AI 禁区(只建议不拍板) | — | AI 可拍板 | 部分限定 | 全部人落锤 | 2% |
| B 类审核防自动化偏见(禁一键通过 + 出处强制核对) | — | 一键通过 | 部分 | 无一键通过+出处核对 | 2% |
| 审核分级 + 置信度门(低置信自动转人工) | — | 无 | 仅分级 | 分级+置信度门 | 1% |
| Agent 默认全禁 + 逐项最小授权(防过度代理) | **P0** | 默认全开/借管理员 | 部分 | 默认全禁+scoped 白名单 | 3% |
| Agent 身份化 + 读写分离(无致命三角) | P1 | 借管理员/三角凑齐 | 部分混用 | 独立身份+读写分离 | 2% |
| 危险操作审批门 + 预算/次数熔断 | P1 | 无 | 仅审批门 | 审批门+硬熔断 | 1% |
| 实验追踪(MLflow,可复现) | **P0** | 无 | 部分 | 全量记录 | 4% |
| 模型注册表 + 一键回滚(≤5 分钟) | **P0** | 无 | 注册表 | 注册表+回滚 | 4% |
| 监控告警(基建层 + 模型层) | **P0** | 无 | 1 层 | ≥2 层+值班告警群 | 4% |
| 数据/特征版本管理(DVC) | P1 | 无 | 手动 | 自动化 | 1% |
| 流水线编排(Prefect/ZenML) | P1 | 人手脚本 | 半自动 | 一条命令全自动 | 1% |
| 部署 + 金丝雀 + 自动回滚 | P1 | 直推 | 有灰度 | 金丝雀+自动回滚 | 1% |
| 数据漂移 / LLM 幻觉监控 | P2* | 无 | 部分 | 自动化 | 1% |

> *P2 为默认;**输入易变场景**(制造/风控/推荐)数据漂移监控升 P1;**LLM/Agent 场景**(医疗 RAG/客服/法律)幻觉监控升 P0。
> 治理类(人机边界/权限/审核)实操拆解见 `references/permissions-and-oversight.md`;MLOps 骨架类实操见 `references/mlops-playbook.md`。
> **监控告警这里只评"有没有"(0/1/2 层 + 值班告警群)——这是决策门(事前资格)。** 上线后这些监控跑起来读出什么数(TTV / 评估达标率走低 / 激活率 / NRR…),属于**运营门**的度量,见 `references/fde-metrics.md` 四层指标。**决策门不对运营门套 Go/No-Go**:此处阶段三权重(30%)与阶段四打分**完全不动**——监控是上生产的入场券,不是价值已兑现的证明。

**阈值:** ≥ 75% GO(可上生产)/ 40%–74% HOLD(仅内部试点,禁对外称"上线")/ < 40% = **NO-GO 红线**。

> 🔴 **红线触发器(无论总分,P0 三件套缺一即 No-Go):** 无实验追踪 + 无模型回滚 + 无监控告警 = **直接 No-Go**,不得上生产。95% 的项目死在缺这三件基础设施,不是模型不够大。

> 🟠 **架构红旗(Hold 信号):** 若出现"层层 agent hierarchy 但无路由设计 / 无控制面-执行面分离",记为架构 Hold——典型的"用 agent 数量掩盖路由设计懒惰",延迟和成本会失控。建议先收敛为**单 agent + 强路由**(详见 `references/production-architecture.md` 第三节)。

> 🟠 **决策闭环红旗(Hold 信号):** 若客户诉求是"决策闭环"(Reason-Decide-Act 层)却没规划 Ontology 与 Decision Object——AI 输出只是一段聊天记录、无 evidenceRefs/rulesMatched/traceId、不可审计、不可回写——记为架构 Hold。模型再强也进不了业务责任链,B 类价值区做不出来。先补业务语义层与可治理决策对象设计(详见 `references/decision-os-playbook.md`)。

> 实操细则(每组件合格检查点 / 致命场景 / 起步操作 / P0-P2 工具栈)见 `references/mlops-playbook.md`。

## 五、总分决策矩阵

```
整体判定 = 四阶段加权总分 + 一票否决规则
```

| 加权总分 | 整体判定 | 动作 |
|---|---|---|
| ≥ 75% 且无阶段 No-Go | 🟢 **推进** | 按四阶段顺序执行 |
| 50%–74% 且无阶段 No-Go | 🟡 **有条件推进** | 优先补最弱阶段,设硬性补救截止日 |
| 任一阶段 No-Go | 🔴 **一票否决** | 停在该阶段,升级决策:放弃 / 重构范围 / 重新分配利益 |

**一票否决优先级(最致命的四张红旗,任一出现即整体 No-Go):**
1. 客户不愿给真实数据样本(数据基础不存在)。
2. 无监控 + 无回滚就要上生产(工程基础不存在)。
3. 关键隐性知识持有者公开抵制且无法接触一线(人际基础不存在)。
4. C 类不可逆决策交给 AI 拍板,或 Agent 默认全开 / 借管理员权限跑生产(权限与监督基础不存在——一次越权或自信犯错,就足以摧毁整套信任)。

## 六、话术库扩展版

### 1. 启动会预防针话术(对管理层,项目第 1 天)

> "各位领导,我想先把丑话说在前面,这样后面大家都不意外。AI 项目有个规律:前一个月大家会看到很快的 demo 进展,那是水面上的 40%;但真正决定它能不能用的,是水面下的 60%——系统集成、可靠性、合规、数据清洗,这段时间看起来'没动静',其实是项目最吃劲的阶段。我会用每两周一个可验收的小节点,让大家始终看得见进展。如果中途我说'卡住了',那是我在对大家负责,不是在找借口。我们的目标不是快,是它真的能扛事。"

### 2. 利益绑定话术(对被 AI 触动利益的中层/老员工,私下)

> "X 哥,这个系统搞起来,您的角色只会更重,不会更轻。我把判断逻辑挂您的名字,对外汇报就说这是'X 师傅的经验沉淀',您是总顾问、有最终审核权。说白了,以后这套东西越准,越说明您这些年功夫深;徒弟们用它,等于在学您。您帮我们把把关,功劳是您的,黑锅我们背。"

### 3. 反向承诺话术(卡点暴露时,对老板)

> "X 总,有个卡点我得如实跟您说:[现状事实]。我没有办法承诺'下周就好',那样说是不负责任的。我能给您的应对计划是:[A 方案 / B 方案],预计 [具体时间] 给您明确结论。如果您要的是更快的速度,我们也可以聊聊是不是先把范围收一收,先上能稳的部分。我宁愿现在跟您说难听的,也不愿意两周后给您一个扛不住的东西。"

### 4. 传承话术的场景变体

- **制造业质检老师傅:** "您的眼睛就是标准。我们要做的不是机器替您看,是把您看了二十年的经验存下来,让新来的孩子少走几年弯路。这系统叫'X 师傅质检法',您来定规矩。"
- **医疗资深医生:** "主任,您的临床判断是科室的财富。我们想帮您把这套判断逻辑结构化,既能让年轻医生学到,也能让您从重复的初筛里解放出来,把时间留给真正复杂的病例。"
- **法律/合规资深:** "X 老师,这些 case 的拿捏全靠您的经验。我们想把您的判断标准沉淀成知识库,让团队有据可依,您也不用反复回答同样的问题。署您的名字,您来把关。"

### 5. 第 35 天话术的变体(管理层焦虑加剧时)

> "X 总,我知道您着急看到效果,这个心情我完全理解。我们现在的进度是这样的:[已完成的不性感里程碑,如数据管道调通、监控上线]。这些看着不起眼,但没有它们,前面 demo 再好看也上不了线。我预计再 [N] 周,我们就能在真实业务流上跑第一批小流量,到那时候您会看到真正能用的东西,而不是 demo。这两周如果您需要,我可以每天给您一封两句话的进展同步。"
