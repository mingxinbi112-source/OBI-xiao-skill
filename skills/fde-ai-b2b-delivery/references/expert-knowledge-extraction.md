# FDE 专家知识抽取 SOP 与配合机制 Playbook

本文件是 `SKILL.md` 阶段二「人际破局与抢救隐性知识」的**深化展开**。阶段二解决了第一层问题——**让专家愿意配合**(话术重构 / 荣誉绑定 / 痛点降维);本文件解决两个更深的、决定项目能不能沉淀出真东西的问题:

1. **配合了之后,怎么把专家脑子里的隐性知识抽成可执行 SOP?**(不是让专家写,是工程师抽)
2. **用什么结构性机制,让一个理性上该防着你的专家真配合?**(不是靠情怀,是动结构)

核心信念(贯穿全篇):**专家的价值全在分叉判断上,不在动作顺序上。把专家知识写成「第一步、第二步」的线性流程一定失败。真正值钱的 SOP 是决策树——而例外条款,往往占专家真实水平的一半以上。**

## 一、第一原则:抽象是工程师的活,不是专家的活

落地 FDE 最先撞的墙,是专家「只能实操、无法抽象」。**这不是专家的缺陷,而是专业知识的本质**——知识工程里称为**隐性知识(tacit knowledge)**,正如 Polanyi 那句「我们知道的比我们能说出来的多」。

所以第一条铁律:**不要指望专家做抽象**。逼专家写 SOP,他要么写成正确的废话(「具体情况具体分析」),要么写成跟实际操作完全脱节的教科书。两段都会让你拿到一份落灰的文档,却抽不到真知识。

正确的分工是:
- **专家负责两件事:实操、判对错。**
- **工程师负责一件事:把实操抽象成结构。**

这条原则决定了下面所有手法的方向——你不问专家「方法论」(他答不出),你抓他「在哪里停顿、用什么判据、什么情况会破例」(他答得出,因为这是他肌肉记忆的一部分)。

> 与 `decision-os-playbook.md` 的呼应:专家脑子里的判据,就是 Ontology 里「业务规则」的来源。没有这一步抽取,Ontology 永远停在 L0(散落在文档/人脑),决策闭环就是空中楼阁。

## 二、现场抓取三手法:别问「你怎么做」,要抓「你在哪停顿」

直接问方法论必然失败。有效的手法有三个,**核心思路都是绕开专家不擅长的「归纳」,走他擅长的「回忆具体事」**。

### 手法一:影随 + 出声思考(think-aloud)

坐在专家旁边看他真干活,要求他**边做边把脑子里的念头念出来**。

- 关键不是听他「做了什么」(那部分他通常顺畅流过,不重要);
- 关键是抓他**在哪里停顿、皱眉、回头看一眼别的数据、叹口气重做一遍**——**那些停顿点就是决策点,就是 SOP 要固化的地方**。
- 顺畅流过的部分反而不值钱(说明是常规动作,新手也能学会);**卡顿、犹豫、回头核对的瞬间,才藏着专家的判断力**。

**FDE 现场动作:** 带个本子,每次专家停顿就记一个时间戳 + 一句话(「这里停了,回头看了 Y 表」)。一天下来,这些停顿点连起来,就是候选决策点清单。

### 手法二:关键决策法(Critical Decision Method, CDM)

让专家**回忆一个具体的、非典型的案例**(「上次那个差点出事的单子」「上个月那个最棘手的客户」),而不是问「一般怎么做」。

- 人对**具体事件**的记忆精度,远高于对**流程归纳**的记忆精度。
- 围绕这一个案例,做四层深挖:
  1. 当时你**第一眼注意到**了什么信号?(触发)
  2. 你拿哪几个数/信息**做判断**?阈值大概在哪?(判据)
  3. 你**做了什么**?(动作)
  4. 什么情况下你会**换个做法**?(例外——最值钱)

一个非典型案例挖透,胜过十句「我们一般会先...然后...」。

### 手法三:对比法与反例法

让专家**评判差异**和**边界**,而不是描述流程。

- **对比法:** 「这个事,高手和新手会怎么做错?」——差异点就是知识点。新手做错的那个地方,正是专家隐性判据发挥作用的地方。
- **反例法:** 主动构造**违反直觉的边界 case**丢给他判。他每一次「这个不行,因为……」都在暴露一条**隐藏规则**——一条他平时不会主动说、但实际在用的规则。

> 三手法可叠加:CDM 挖一个典型案例 → 影随抓现场停顿点 → 反例法逼出例外条款。一次高质量访谈,三者并用。

## 三、专家术语 = 被压缩的判据(解压缩逼问链)

专家黑话之所以难沉淀,是因为**一个词打包了一堆隐含判据**。撬它的方法是不断逼问边界,直到黑话被拆成可判定的规则。

### 经典解压缩链(直接照用这个追问节奏)

> 专家说「这个客户**感觉不太行**」。别停在这。追问:
> - 什么样算「不太行」?→ 回款慢。
> - 多慢?→ 超 60 天。
> - 只要超 60 天就是?→ 不,老客户超 60 天没事,新客户超 30 天就要警惕。
> - 那新老以什么划分?→ 合作满 1 年且累计订单 > 50 万。
> - 还有别的触发吗?→ 有过一次拖延还款史的,不管新老都警惕。

追到这里,「感觉不太行」这句黑话就被拆成了 **「客户类型(新/老/有过违约)× 账期阈值(30/60 天)× 历史违约记录」** 的可判定规则。

**术语等于压缩的判据,工程师的工作就是解压缩。** 每一句专家黑话(「这个料有点漂」「这个 case 拿不准」「这单有风险」),都值得用同一条逼问链追到底。

### 逼问话术模板(现场可照念)

> 「您说的『X』,我怕我理解偏了。能不能帮我卡几个边界:
> - 什么情况下**一定算** X?
> - 什么情况下**看着像但不算**?(这一问最关键,逼出例外)
> - 这个判断,主要看哪几个数/信息?大概的线在哪?
> - 有没有**反例**——明明满足条件但您反而没这么处理的?」

**第二问(「看着像但不算」)是整条链的钥匙**——它直接逼出例外条款。

## 四、SOP 的形态:写决策树,不写步骤流水

这是最多人做错的地方。把专家知识写成「第一步、第二步、第三步」的线性流程**一定失败**,因为专家的价值全在分叉判断上,不在动作顺序上。

正确的 SOP 是**决策单元**,每个单元四要素:

| 要素 | 抓什么 | 举例(质检老师傅) |
|---|---|---|
| **触发** | 什么信号让专家开始注意(「看到 X 就警觉」) | 焊缝颜色发暗 / 尺寸公差逼近上限 |
| **判据** | 他拿哪几个变量做判断、阈值是多少 | 颜色深度 × 位置 × 批次历史 |
| **动作** | 判断后做什么 | 降级 / 返工 / 放行 / 升级复核 |
| **例外** | 「但如果……就不这样」——**这一条最值钱** | 同样发暗,但若是老供应商+首件合格,降为抽检 |

**例外条款往往占专家真实水平的一半以上。** 一份没有例外分支的 SOP,等于把专家降维成了新人——它能处理 80% 的常规情况,却在剩下 20% 要命的情况上和新人犯一样的错。

### 决策树 ↔ Ontology/Action 的映射

决策树的四要素,直接对应 Decision OS 的可治理产物(见 `decision-os-playbook.md`):

- **触发 + 判据** → Ontology 里的**业务规则**(可被引擎执行);
- **动作** → **Action 模板**(走 Propose→Approve→Execute→Audit→Rollback 生命周期);
- **例外** → 规则的**优先级/覆写条件**(更高优先级的规则)。

抽出来的决策树不是一份文档,而是**能被系统直接调用的规则 + 动作资产**——这才是「把经验沉淀成可执行资产」的真正含义,也呼应 SKILL.md 阶段二「利益绑定」里「沉淀为本体对象/规则/Action 模板而非文档」。

> 与 `permissions-and-oversight.md` 的映射:每条「动作」要标注决策权分类——A 类(自动执行)/ B 类(AI 建议+人审)/ C 类(AI 禁区只建议不拍板)。例外条款触发的往往是 B/C 类,必须留人工落锤口。

## 五、闭环验证:让专家「改」,不要让他「写」

人**批判**比**创造**强得多。所以抽取流程永远是:

```
工程师起草一版初稿(哪怕故意不完美)
    ↓
拿给专家骂(他会忍不住指出哪里不对)
    ↓
他改 → 暴露的修改点 = 漏抽的隐性规则
    ↓
拿一个新 case,让 SOP 和专家同时跑
    ↓
结论一致? → 不一致处 = 还没抽到的规则 → 回到第一步迭代
```

**用一个故意不完美的初稿当诱饵,是撬隐性知识最实用的技巧。** 你给专家一张白纸让他写,他写不出;你给他一版「这里有点问题」的草稿,他能精准地告诉你哪里不对、为什么不对、什么情况下不对——后者正是隐性知识。

### 为什么不能让专家「写」

- 写 → 他给你「正确的废话」或「脱节教科书」(见第一节);
- 改 → 他必须对照真实判断来否定你的错误,这个否定过程**强迫他显式化自己的判据**。

**让专家保持在「判对错」的位置上,永远不要把他推到「创造/归纳」的位置上。**

## 六、AI 在抽取链路里的角色(成本砍一个量级,但有一道不可替代)

大模型第一次让工程师有工具补上「不懂业务」这个短板,它把「抽业务逻辑」的成本塌了一个量级。具体在抽取链路里,AI 能干三件事:

1. **录屏转决策点:** 全程录下几小时的影随 + think-aloud,让模型自动把停顿点、回头核对的瞬间**聚类成候选决策点清单**——人肉看几小时录像挑点,是 FDE 过去最劝退的脏活。
2. **起草决策树初稿当诱饵:** 基于访谈纪要,直接吐一版决策树初稿(四要素填好,故意留几个可疑的判据/例外),拿去给专家「改」——这比工程师从零写初稿快一个量级,且初稿的「可疑处」正好是诱饵。
3. **自动构造边界 case 去考专家:** 给模型当前已抽出的规则,让它生成「违反直觉的边界 case」丢给专家判,逼出新的例外条款。这是反例法的工程化。

**但有一道 AI 替代不了:判对错的最终权必须在专家手里。** 否则模型会把专家的**偏见和智慧一起学进去**——专家某个固执的错误习惯、某条过时的规则,AI 会忠实地复刻,没有人在环里校验,你沉淀的可能是一套**自信的错误**。这和 `permissions-and-oversight.md` 的「破自动化偏见」是同一件事的两面:审核要有效,必须有真人在环、且被设计逼着真的审。

> 落地红线:AI 可以起草、可以聚类、可以构造 case,但**「这条规则对不对、要不要进生产」的最终签字权,是专家(或其授权的复核人)的,不是模型的**。

## 七、专家凭什么配合你:五种结构性机制

这是落地 FDE 真正会死人的地方。想想专家的处境:**你来的目的,就是把他脑子里那套让他不可替代的东西抽出来变成 SOP 和 AI。你等于在他面前组装一台「替换我自己」的机器。** 从他的利益看,认真配合你是非理性的。

所以**指望靠讲情怀、谈战略让他掏心窝子必然失败——你得动结构**。现实里能让专家真配合的,只有这五种机制,按「撬出隐性知识的力度」从弱到强排:

### 机制 1:上级硬性授权 + KPI 绑定(底线,但最弱)

老板一句「配合一下」+ 把配合度写进他的 KPI。

- **有强制力,但撬不出隐性知识。** 换来的往往是**物理在场、精神缺席**——他会给你正确的废话,把真正的例外判据咽回去。
- 它是底线(没它你连人都见不到),但**必须叠加下面几条**,单用它必败。

### 机制 2:重新定义他的角色(从「干活」变「定规矩」)

不是「我来把你的活自动化掉」,而是「**这套系统上线后会署你的名,全公司新人都按你定的规矩干,你从一个干活的变成定规矩的**」。

- 让他意识到:知识被沉淀后**不是被替换,而是被放大**——他的判断力从只覆盖自己经手的单子,变成覆盖整个部门。
- 这是 SKILL.md 阶段二「荣誉绑定」的底层逻辑:**冠名 / 署名 / 审核权**都是「放大而非替换」的具体形式。
- 对**职业荣誉型**专家(见第八节),这一招往往单独就够。

### 机制 3:先帮他干掉最烦的脏活(先给糖,再要秘密)

第一个切片**别去碰他的核心机密判断**,去替他干那些每天都嫌烦的重复劳动——填表、跑数、抄录、应付新人重复提问。

- 他一旦尝到甜头,防御心会松,**配合意愿从被迫变成主动**。
- 这是 SKILL.md 阶段二「痛点降维」+ 阶段四「land-and-expand 薄切片」的共同逻辑:**先给糖,再要秘密。顺序不能反。**
- 反例:一上来就奔着他最核心、最不可替代的判断逻辑去抽,等于当面宣战。

### 机制 4:直接的利益绑定(让他在系统成果里有份)

项目奖金、专家分成、内部知识产权署名、系统上线后的「专家咨询费」。

- 当 **SOP 跑得越好他拿得越多**时,他才会把压箱底的例外条款也交出来。
- 这是机制 2(荣誉)的硬化版:荣誉对打工型专家不够,得有真金白银。
- 落地:在合同/项目章程里**白纸黑字**写明专家的分成/署名/奖励,不要口头承诺(口头承诺=机制 1 的 KPI 绑定,最弱)。

### 机制 5:接受撬不出 100%,并设计成不依赖任何单个专家(最强谈判杠杆)

总有专家会**战略性保留最关键的 20% 当护城河**。对策不是死磕一个人,而是:

- **横向找 2-3 个专家交叉验证。** 同一个决策点,让两个专家分别给判据;不一致处,要么是真规则的边界,要么是某人保留了。
- 当他发现**「这套东西没我也在往前走」**,反而会因为怕被边缘化而**主动补全**。

**降低对单一专家的依赖,本身就是最强的谈判杠杆。** 这一条反直觉但最关键——你以为死磕一个专家效率最高,实际上单点依赖让你在任何谈判里都处于下风;横向多源反而让你既有冗余、又有筹码。

> 这一条与 SKILL.md 阶段一「数据成熟度」的红线(必须强制客户提供 3-5 个真实样本)同构:**单点依赖 = 单点失败 = 单点要挟**。数据要多元,专家也要多元。

## 八、专家类型诊断:先出哪张牌

落地 FDE 的下一步很具体:**先判断你面对的专家是哪一型**,这决定了上面五种机制里你该先出哪一张牌。

| 专家类型 | 特征 | 最有效的牌(先出) | 次选 | 慎用 |
|---|---|---|---|---|
| **职业荣誉型** | 在意名声、把专业当事业、享受「被尊重为权威」 | **机制 2**(重新定义角色:定规矩+署名) | 机制 3(干脏活换信任) | 单用机制 1(KPI 显得你不尊重他) |
| **打工型(KPI/钱驱动)** | 把活当工作、算投入产出、不谈情怀 | **机制 4**(直接利益绑定)+ 机制 1(KPI) | 机制 3(干脏活) | 单用机制 2(荣誉对他不值钱) |
| **防御型(强烈不安全感)** | 怕被替代、明显保留、话只说一半 | **机制 5**(先建第二个专家源,打破单点) + 机制 3(干脏活降防备) | 机制 4(利益换秘密) | 直接施压(越压越藏) |
| **濒临退休型** | 无利益冲突、愿意传承、但精力/时间有限 | **机制 2**(署名传承,留下名声) | CDM 深挖典型案例 | 长周期影随(他没时间) |

**诊断时机:** 在阶段一 mini 验证面见专家时(见 `pre-signing-audit-toolkit.md` Day 3)就同步做这个判断——看他怎么谈自己的工作(谈「规矩/标准/徒弟」= 荣誉型;谈「绩效/奖金/划算」= 打工型;回避核心问题/话只说一半= 防御型)。诊断结果直接决定阶段二先出哪张牌。

> 误判代价:对打工型专家空谈荣誉(机制 2),他会觉得你在画饼,更防着你;对荣誉型专家谈钱(机制 4)谈得太直白,他会觉得被冒犯。**先诊断,再出牌。**

## 九、可勾选检查清单

### 抽取方法是否到位
- [ ] 没有让专家「写 SOP」,而是工程师抽、专家「改」
- [ ] 至少用过三手法之一(影随 think-aloud / CDM 关键案例 / 对比反例),抓到了**停顿点**而非流程
- [ ] 对每句专家黑话,都做过解压缩逼问(尤其问过「看着像但不算」的边界)
- [ ] SOP 写成**决策树**(触发/判据/动作/例外),不是线性步骤流水
- [ ] 每个决策单元都有**例外条款**(没有例外的 SOP = 把专家降维成新人)
- [ ] 用**故意不完美的初稿**当诱饵,迭代过至少一轮(专家「改」出了新规则)

### 配合机制是否结构化
- [ ] 已诊断专家类型(荣誉型 / 打工型 / 防御型 / 濒临退休型),并据此选了先出的牌
- [ ] 五种机制里**至少叠用了 2 种**(单用机制 1 = 必败)
- [ ] 第一个切片**没碰核心机密判断**,而是先干了脏活(机制 3 顺序正确)
- [ ] 横向有 **≥2 个专家交叉验证**,不依赖单点(机制 5 落地)
- [ ] 利益绑定是**书面**(合同/章程),不是口头承诺

### 边界与闭环
- [ ] AI 起草了初稿/聚了决策点/构造了边界 case,**但判对错的最终签字权在专家**
- [ ] 抽出的决策树已映射到 Ontology 规则 + Action 模板(不是又一份落灰文档)
- [ ] 每条「动作」标注了决策权分类(A/B/C),例外条款触发的留了人工落锤口
